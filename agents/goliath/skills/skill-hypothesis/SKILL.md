# skill-hypothesis — Голиаф

LLM-driven генератор гипотез. Скилл = инструкция Claude по 5 категориям +
правилам квоты.

## Когда вызывать

- **Понедельник, утренний цикл** — новая неделя, квота сбрасывается.
- **Четверг, утренний цикл** — добор второй гипотезы недели если квота не
  выбрана.
- **Внепланово** — если выявилось критичное событие (выгорела кампания,
  модерационный фикс, новый внешний контекст).

## Контракт

**Вход:**
- `snapshot` (от skill-analytics) — за yday + week + MTD
- `current_week_quota_used` — сколько уже создал в эту неделю (0/1/2)
- `active_hypotheses` — список pending+discussing proposals категории
  `new_hypothesis` (чтобы не дублировать)

**Выход** — список proposal-кандидатов категории `new_hypothesis`,
готовых к insert через skill-proposals + одна `H<NN>.md` страница в
Wiki/.../hypotheses/ через Edit/Write tool. Структура proposal:

```json
{
  "category": "new_hypothesis",
  "product": "openclaw",
  "campaign_id": null, "ad_group_id": null, "ad_id": null,
  "description": "**H09** Узкий сегмент М 40-50 руководители на openclaw...",
  "reasoning": "openclaw накопил 100+ конверсий, ARPL@1м стабилен 1700₽...",
  "proposed_action": {
    "tool": "create_microcampaign",
    "args": {"hypothesis_id": "H09", "type": "narrow-segment", "expected_cost_week_rub": 7000}
  },
  "ttl_hours": 48
}
```

## 5 категорий гипотез

### 1. Winner-amplification

**Триггер:** в snapshot есть кампания/объявление с ROAS@1м ≥ 130% за 7 дней
при ≥ 5 лидов.

**Что предлагаем:** снять паттерн (формула title/body, оффер) → передать в
[[skill-ad-copy]] для генерации 3-4 вариаций «в этом стиле». Тестировать
параллельно с оригиналом.

### 2. Visual-test

**Принцип Валерия:** визуал > текст. Тестируем заголовок, визуалы
рандомизируем.

**Что предлагаем:** на лучшей кампании — 4 визуала с одним и тем же
текстом (контролируем переменную). Метрика успеха — CPL ↓ ≥15%.

### 3. Narrow-segment

**Триггер:** на кампании накоплено 100+ конверсий → можно резать узко.

**Что предлагаем:** микро-РК на узком сегменте возраст × гео × пол на
основе [[Демо покупателей по кампаниям Голиафа]]. Бюджет 5-10К/нед.
Долгосрочно: 30-50 микро-РК × узкие связки.

### 4. New-setting

**Открытые кандидаты:**
- Look-alike от Яндекс.Аудитории (база покупателей 90д)
- Площадки конкурентов
- Расписание (минус-коррекция выходных)
- Новые форматы РСЯ (если не использованы)

### 5. Anti-burnout

**Триггер:** кампания с ROAS@1м падает 2 недели подряд по сравнению с
прошлым месяцем (см. [[Зерокодер — кампании выгорают 3-4 мес]]).

**Что предлагаем:** запуск НОВОЙ кампании на том же продукте с другим
оффером/лендингом. Реанимация выгоревшей не работает.

## Квота

- **2 гипотезы в неделю** (Пн → Вс).
- **Вне квоты** — можно предлагать всегда с пометкой `вне квоты, причина X`
  в `description`.
- **≤ 5 активных одновременно** (защита от потери управляемости).
- Перед предложением проверить `active_hypotheses` чтобы не дублировать.

## Алгоритм для Claude в утреннем цикле

1. Прочитать snapshot.mtd.per_product, выявить:
   - кандидаты на winner-amplification (ROAS@1м ≥ 130% за 7д при leads ≥ 5)
   - кандидаты на narrow-segment (cumulative conversions ≥ 100)
   - кандидаты на anti-burnout (тренд по weekly snapshots)
2. Прочитать `Wiki/shared/audiences/Демо покупателей по кампаниям Голиафа.md`
3. Прочитать `Wiki/channels/yandex-direct/learnings/` за последние 30 дней
4. Сгенерировать 1-2 гипотезы, каждая с:
   - формулировкой (1 фраза + развёртка)
   - test_plan (что измерим, за сколько дней, на каком трафике)
   - success/failure criteria
5. Для каждой гипотезы — создать страницу `Wiki/channels/yandex-direct/hypotheses/H<NN>.md`
   по шаблону `_templates/Гипотеза.md` (если шаблон есть)
6. Создать proposal через skill-proposals.insert
7. В отчёте Валерию упомянуть: «новая гипотеза H<NN>: <фраза>; см.
   [[H<NN>]]; принять? обсудим в Claude Code»

## Инварианты

- **Цикл сделки 10 дней** — гипотезы про ROAS не оцениваем раньше 14 дней.
  Гипотезы про CPL — можно через 7 дней.
- **Автовебинар лаг** — гипотезы про доходимость/viewers не оцениваем
  раньше 5-7 дней. Лид сегодня → вебинар завтра/послезавтра, может прийти
  и на второй вебинар позже в месяце. `viewer_rate_pct` для свежих лидов
  всегда занижен.
- **Тексты пишет skill-ad-copy**, не сам skill-hypothesis.
- **Баннеры** — ставим ТЗ через skill-creative-banner; в Phase 1 Валерий
  одобряет/правит.
- **Одна гипотеза = одна страница** `H<NN>.md`. Номер берём как
  max(H_NN) + 1 из существующих файлов в `hypotheses/`.
